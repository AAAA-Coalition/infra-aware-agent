# infra-aware-agent

Three small tools so that an AI agent **knows the infrastructure it works on**
— from measurement, refreshed every day, and recalled at the moment it matters.
Python, standard library only, with planted witnesses and mutation checks.

| tool | what it does |
|---|---|
| `data_catalogue.py` | measures what **data** each host holds: data directories, SQLite and Postgres databases with row counts, the systemd unit that writes each one, its rights, and a **world-readable** flag |
| `recall_hook.py` | a Claude Code `UserPromptSubmit` hook: when the user's message mentions something already mapped or a problem already solved, one short **pointer** is added to the agent's context |
| `model_probe.py` | exercises every model of a LiteLLM gateway **per usage** (text, vision, embeddings), **fallbacks disabled**, and says who depends on it |

They answer one complaint from the person we work for, close to verbatim:
*"you know nothing, you don't know where it is, you have to search, and we
solve the same problem dozens of times."* Everything the agent needed was in
files it could read. Nothing made it read them.

## 1. Data catalogue

**What it cost.** Our map of the system listed services, ports, MCP tools and
timers. It did not list the two largest assets on the host: a mail archive of
tens of gigabytes and a search index of several hundred thousand rows. Nobody
had forgotten them. **The map simply never looked at data**, so every agent
asking *"where are the mails?"* started from zero.

**What it records**, per host, run as root:

- directories above a threshold under configurable roots (same filesystem only, like `du -x`);
- SQLite databases: tables and row counts;
- Postgres databases inside Docker containers: largest tables, estimated rows, size;
- for each: the unit(s) that mention its path — *who writes it* — its mode, owner, and a **WORLD-READABLE** flag.

**What it never does**: read a row, print a value, or open a database whose
path matches `CATALOGUE_NEVER_OPEN` — that one is **counted, never opened**.

**Two refusals.** A host that cannot be read is written `BLIND`, never as an
empty section: an empty host and an unreadable one must not look alike. And if
any string shaped like a secret (API-key prefixes, bot tokens, GitHub tokens,
long base64 runs) appears in the rendered catalogue, **nothing is written**
(exit 3). The detection is by **value shape**, not field name: masking by field
name is how a secret nested in an unexpected field leaks.

```bash
python data_catalogue.py --local --out CATALOGUE.md          # this host
python data_catalogue.py host-a host-b --out CATALOGUE.md    # over SSH: the script is sent on stdin
```

Run it on each host from a timer (`examples/data-catalogue.*`). A map
regenerated by hand from a laptop was out of date the day after.

## 2. Recall hook

**Pointers, not content.** Each entry of `recall.json` has a regular
expression and one line: a path, a count, a command. When the user's prompt
matches, that line is printed on stdout, which Claude Code adds to the agent's
context ([hooks reference](https://code.claude.com/docs/en/hooks)). At most 5
lines and 2 400 bytes per message.

```
RECALL (recall.json) -- what already exists about what this message mentions:
[P-INVENTORY-GAP] An asset exists but no map or inventory lists it. -> Data catalogue measured every day on each host; ...
[A-MAIL-ARCHIVE] MAIL ARCHIVE: /srv/mail-archive on host-a (written by mail-sync.service every 20 min); ...
```

Two kinds of entries:

- **assets** — where something is;
- **problems** — symptom, cause, solution, guard: a problem already solved
  once. `recall_hook.py --render RECURRING_PROBLEMS.md` turns the same file into
  a readable registry, so the human list and the recalled list cannot drift.

**Why a hook and not an instruction.** An instruction *"check the catalogue
first"* depends on the agent remembering to. The hook starts from the message,
deterministically. A banal message (*"ok thanks"*) triggers nothing: an alarm
that always rings gets muted.

`recall.example.json` is an example with generic entries; copy it to
`recall.json` and write your own.

## 3. Model probe

**What it cost.** A vision model had been returning `404` for an unknown time.
We found it **by chance**, while building something else. Nothing had seen it:

- the gateway was *active* — a live service is not a live model;
- the agents *answered* — **through the fallback**. A working fallback hides a
  dead model.

So each model is called with `disable_fallbacks: true`, and the test depends on
what it is used for:

| kind | test |
|---|---|
| text | *"answer with the single word READY"* — the word must come back |
| vision | a PNG showing a **random** 4-digit number, generated in pure Python — the digits must be read |
| embeddings | a non-empty vector |

States: `OK`, `SLOW`, `WRONG` (answers, fails the test), `DEAD`. Then the
severity comes from **who depends on what** (`PROBE_CONSUMERS`,
`PROBE_AGENT_STORE`, `PROBE_NEEDS`):

| | condition | exit |
|---|---|---|
| **SEVERE** | a used model is dead or wrong and **no** fallback is alive — or a used model is absent from the gateway | 1 |
| **DEGRADED** | a used model is dead but a fallback answers | 0, reported |
| noted | a dead model nobody uses | 0, reported |
| **BLIND** | no key, gateway unreachable, or **every** model dead (that is the gateway or the key) | 2 |

**DEGRADED exists because of our first real pass.** A model used by three
agents returned `503`; its fallback answered. Calling that *severe* every
morning would have taught everyone to ignore the alarm. The first pass found
two such degradations that the fallbacks had been hiding.

**Seen end to end** against a local LiteLLM proxy (1.108.3) with mock models:

```
  chat-ok        text    OK      0.1 s  used by: agent B
  chat-dead      text    DEAD    9.5 s  used by: agent A  -- HTTP 500
  backup         text    OK      0.0 s  (no consumer)
  vision-model   vision  WRONG   0.0 s  used by: agent V  -- answer without '5528': 'I cannot read it'
  DEGRADED chat-dead: dead, served by backup
… 1 severe: vision-model ; 1 degraded            (exit 1)
```

The same `chat-dead`, called **without** `disable_fallbacks`, answered
`READY` — served by `backup`. That is exactly the masking the probe exists to
remove.

## The witnesses, and the mutations

```
$ python test_all.py
== data_catalogue
  ok   5. an unreadable host is BLIND, not empty
  ok   7. a secret shape in the facts -> nothing is written
  ok   10. a never-open database is not opened
  …
== recall_hook
  ok   5. a banal message triggers nothing (an alarm that always rings gets muted)
  ok   7. the cap holds on a message touching everything (10 entries match, 5 lines kept)
  …
== model_probe
  ok   5. fallbacks are DISABLED: the model is judged, not the chain
  ok   9. dead + live fallback = DEGRADED ; dead + dead fallbacks = SEVERE ; unused = nothing
  …
== mutations: each broken guard must be caught
  ok   secret-shape guard disabled -> caught
  ok   never-open list ignored -> caught
  ok   recall cap removed -> caught
  ok   fallbacks no longer disabled -> caught
  ok   a live fallback no longer downgrades to DEGRADED -> caught

TOTAL: 0 witness failure(s), 0 mutation(s) not caught
```

31 witnesses. **The mutations earned their place before publication**: the
first run reported `recall cap removed -> NOT caught`. The cap witness compared
the output with the module's own constant, so when the constant was broken the
witness moved with it — and the test message did not even match enough entries
to reach the cap. A witness that reads the value it is supposed to guard is
green by construction.

## Install

```bash
git clone https://github.com/AAAA-Coalition/infra-aware-agent
cd infra-aware-agent
python test_all.py
```

- **Catalogue**: `examples/data-catalogue.service` and `.timer` (as root, once per host).
- **Probe**: `examples/model-probe.service` and `.timer`. The key is read from a
  **file** (`PROBE_KEY_FILE`, bare key or `LITELLM_MASTER_KEY=` line), never from
  the command line. With `PROBE_CONFIG`, models and fallbacks come from the
  LiteLLM config; without it, from `GET /v1/models` and no fallback is known.
- **Recall**: copy `recall.example.json` to `recall.json`, edit it, and add the
  hook from `examples/claude-settings.json` to `.claude/settings.json`.

| variable | tool | meaning |
|---|---|---|
| `CATALOGUE_ROOTS`, `CATALOGUE_MIN_MB`, `CATALOGUE_DEPTH` | catalogue | where to measure (default `/opt:/srv:/var/lib:/home`, 200 MB, depth 3) |
| `CATALOGUE_NEVER_OPEN` | catalogue | path substrings of databases counted but never opened |
| `CATALOGUE_UNITS_DIR` | catalogue | unit files used to find writers (default `/etc/systemd/system`) |
| `RECALL_FILE` | hook | the JSON (default `recall.json` beside the script) |
| `PROBE_GATEWAY`, `PROBE_KEY_FILE`, `PROBE_CONFIG` | probe | gateway, key file, LiteLLM config |
| `PROBE_CONSUMERS`, `PROBE_AGENT_STORE`, `PROBE_NEEDS` | probe | who uses which model |
| `PROBE_KINDS`, `PROBE_SLOW_S`, `PROBE_OUT_DIR` | probe | kind overrides, latency floor, result directory |

Python 3.8+. No dependencies. The catalogue collector runs on Linux (it is
tested end to end on Linux; on Windows only its rendering and SQLite parts are).

## Limits, stated

- **The catalogue measures; it does not understand.** It tells you a database
  has a `messages` table of 2 million rows and which unit writes it, not what
  the rows mean. The writer is *probable*: a unit that mentions the path.
- **Postgres row counts are estimates** (`reltuples`), and only databases inside
  Docker containers are found. A Postgres installed on the host is not.
- **The secret guard is a last line**, a few value shapes. Run a real scanner
  ([gitleaks](https://github.com/gitleaks/gitleaks), trufflehog, detect-secrets)
  on anything you publish.
- **Recall is regular expressions.** It misses a paraphrase its pattern did not
  foresee and fires on a word used in another sense. Patterns are cheap to
  adjust; keep each line short.
- **The probe judges one call per model per pass.** A model that fails one call
  in ten will often pass. Between passes, LiteLLM's own health checks and the
  fallback headers in responses cover the gaps — use them too.
- **The vision test reads printed digits.** It proves the model sees an image,
  not that it understands a scanned document.
- **Kinds are guessed from model names** (`embed`, `vision`, `-vl`, `ocr`);
  override with `PROBE_KINDS`.

## Where this sits

We checked before writing this, on 8 November 2026:

| | what it does | what this adds |
|---|---|---|
| [LiteLLM health checks](https://docs.litellm.ai/docs/proxy/health) | `/health` probes every deployment; background checks, per-group scoping, [health-driven routing](https://docs.litellm.ai/docs/proxy/health_check_routing) | a test **per usage** (reading an image, returning a vector), the link to **consumers**, and "dead **without** a live fallback" as the only alarm |
| [osquery](https://github.com/osquery/osquery), Ansible [`service_facts`](https://docs.ansible.com/ansible/latest/collections/ansible/builtin/service_facts_module.html) | query OS state, gather facts over SSH — far more mature | a single file aimed at data: databases with row counts, writer unit, world-readable flag, never-open list, refusal on secret shapes |
| data catalogues such as [DataHub](https://github.com/datahub-project/datahub), [OpenMetadata](https://github.com/open-metadata/OpenMetadata) | schemas, lineage, ownership across an organisation | nothing of that; a daily per-host file that an agent reads in seconds |
| [Claude Code hooks](https://code.claude.com/docs/en/hooks), `CLAUDE.md` memory | the mechanism: `UserPromptSubmit` stdout is added to context; `CLAUDE.md` is loaded whole | a registry of pointers recalled **by pattern**, capped, and the same file rendered as a recurring-problems registry |

Use LiteLLM's health checks **and** this probe: they answer different
questions (*is the deployment up?* against *can the agent that depends on it do
its job?*).

Related, from the same coalition:
[evidence-before-automation](https://github.com/AAAA-Coalition/evidence-before-automation)
(the discipline behind the witnesses) and
[honest-agent-hooks](https://github.com/AAAA-Coalition/honest-agent-hooks)
(two Claude Code hooks that deny instead of warning).
